# Card Pulse MVP定義

> 状態: Active
>
> 最終更新: 2026-09-10

## 検証する仮説

MVPでは、次の仮説を検証する。

1. 異なる情報源から得た価格を、共通形式と追跡可能な出典を保って蓄積できる。
2. カード名だけに依存せず、十分な精度で同じカードを同定できる。
3. 複数店舗の価格差と時系列変化が、仕入れ候補または売却先の判断に役立つ。
4. 小規模な定期収集を、許容できる保守時間で継続できる。

## 対象範囲

対象TCGとMVPの第一選定情報源は[ADR-0009](../adr/0009-pokemon-mvp-sources.md)で決定した。自動取得、保存、fixture、派生集計提供の書面許諾を得るまで、選定情報源へのCollection Workerによる取得は開始しない。

| 項目 | MVPの範囲 |
| --- | --- |
| TCG | ポケモンカードゲーム |
| 店舗 | 晴れる屋2と遊々亭の2店舗。書面許諾後に取得を開始 |
| 補助入力 | CSVまたはJSONによる手動取込1系統 |
| 価格 | 買取価格を優先 |
| 保存 | 比較検証後に選定するサーバー型DB。原本本体は別storageに保存 |
| 照会 | 最新価格、中央値、最高値、最低値、店舗数、鮮度、スプレッド、履歴を返すAPI |
| 実行 | APIとCollection Workerを別サービスとして実行 |
| ローカル開発 | Docker ComposeでAPI、Worker、DB、artifact storageを再現 |
| 試験期間 | 2〜4週間 |

## 対象外

- Xの全自動監視
- X非公式取得を前提とする機能
- 画像だけからカードそのものを識別する機能
- 全TCG・全店舗対応
- リアルタイム更新
- 高可用性、自動拡張、複数regionを備えた本番運用
- Card DiggerのUIまたは商品探索機能
- 正式な掘り出し物スコア
- 商用提供または第三者へのデータ提供

画像OCRとX取得は、構造化Webデータの価値を確認した後に個別の検証として判断する。

## 完了条件

- 2〜3店舗から同じ操作で繰り返しデータを取り込める。
- Collectorごとの差を共通の候補形式へ変換できる。
- 原本から処理実行、抽出結果、観測候補、同定判断、確定観測またはreviewまで追跡できる。
- 必須項目を欠く抽出結果を再処理可能な形で残し、確定した価格観測と区別できる。
- 同じ原本を再投入しても確定した価格観測値が重複しない。
- すべての観測値から、原本URLまたは手動投入ファイルのメタデータまで追跡できる。
- 金額、通貨、価格種別、取得日時、店舗、TCGが欠けた候補を確定データに入れない。
- カード同定が曖昧な候補をレビュー待ちとして隔離できる。
- カード名だけの一致で自動確定しない。
- 任意のカードについて、集計値、鮮度、個別観測値、履歴をCLIまたはJSONで確認できる。
- Card Digger等のクライアントがDBへ直接接続せず、最小APIから相場情報を取得できる。
- API、Collection Worker、DBを別サービスとして起動できる。
- 一つのCollectorが停止しても、保存済みデータの照会と他のCollectorは動作する。
- domain unit test、保存のintegration test、Collector contract test、固定fixtureによるparser regression testが通る。
- バックアップから空環境へ復元できる。
- 試験収集後、データの有用性、取得成功率、未同定率、レビュー時間、保守時間を記録し、継続・変更・中止を判断できる。

## 品質上の不変条件

- 金額は整数の最小通貨単位で保存する。
- 公開日時と取得日時を別の値として保存する。
- 日時にはタイムゾーンを持たせる。情報源がタイムゾーンを示さない場合の解釈をsource文書に記録する。
- 「取得失敗」「正常な0件」「データなし」「古いデータ」「価格0」を区別する。
- 取得原本と価格観測を追記型で保存し、訂正や再解析の履歴を残す。
- processorと同定規則のversionを処理結果と観測結果へ関連付ける。
- 抽出confidenceとカード同定のmatch scoreを区別する。
- 外れ値を削除せず、集計値と個別観測値の両方を参照可能にする。
- 自動同定の誤結合を、未同定より重大な障害として扱う。

## MVP中に決める事項

- 選定した2店舗の取得許諾と取得間隔
- カードを一意に扱うために必要な識別項目
- 鮮度を判定する期間
- 同一原本・同一観測の重複防止キー
- DB製品、hosting方式、必要なbackup・復旧水準
- 価格の訂正、失効、再解析の表現
- 処理実行、抽出結果、観測候補、同定試行の重複防止と派生関係
- 取込、再解析、review確定のtransaction boundary
- Card Diggerへ提供するAPIの詳細な問い合わせ形式

これらは実データを確認してからADRまたは契約文書で決める。
