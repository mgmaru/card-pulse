# ADR-0009: ポケモンカードのMVP情報源に晴れる屋2と遊々亭を選ぶ

- 状態: Accepted
- 日付: 2026-09-10
- 決定者: プロジェクトオーナー
- 置換するADR: なし
- 置換されたADR: なし

## Context

MVPでは、同じTCGの同じカードについて2〜3店舗の買取価格を継続的に比較する。対象を決めるには、価格を表示していることだけでなく、カード番号、セット、レアリティ、版・加工・言語等を原本から識別でき、状態条件と出典を観測ごとに保持できる必要がある。

`CP-0004`では、ポケモンカードゲームを扱う6情報源の公開ページを2026-09-09に少量確認した。[代表サンプル比較](../sources/source-map.md#代表サンプル比較)では、カード名または番号だけでは版、加工、封入状態、同名再録を区別できない一方、TCG、セット、番号、レアリティ、版情報を組み合わせれば比較候補を1件へ絞れる例を確認した。

共通サンプルの`メガレックウザex / M6 / 110/076 / SAR / 日本語`は、遊々亭、晴れる屋2、ドラゴンスターで各1候補になった。遊々亭とドラゴンスターは25,000円、晴れる屋2は33,000円を掲載していた。ただし遊々亭はカード別状態を持たず、晴れる屋2のJSONは状態条件を持たず、ドラゴンスターは状態Aのネット買取参考価格である。カードを照合できても、価格条件が同じとは限らない。

利用条件も選定を制約する。2026-09-09から10にかけた独立再確認では、遊々亭と晴れる屋2のどちらも、自動取得、原本保存、fixture、Card Diggerへの派生集計提供を明示的に許可する条件を確認できなかった。技術候補の選定とCollection Workerの開始を分け、実取得は書面許諾後に判断する必要がある。

## Decision

- 対象TCGにポケモンカードゲームを選ぶ。
- MVPの第一選定情報源を晴れる屋2と遊々亭の2店舗とする。
- 晴れる屋2は、未認証JSONにsource内ID、series、set、カード番号、買取・販売価格があり、全件原本を条件付きGETできる技術的見込みを評価する。titleからレアリティ、版、言語を分解し、番号欠損と同一番号の複数候補はreviewへ送る。
- 遊々亭は、SSR HTMLからset code、source内ID、カード番号、セット、レアリティ、現行買取価格を取得できる点を評価する。打消し表示の旧価格を除外し、名称中の加工・版差分を同定に使う。
- 情報源横断の自動同定には、TCG、セット、カード番号、レアリティ、言語、版・加工・封入状態を使う。情報源内IDは出典追跡と重複防止に使い、共通カードIDにはしない。欠損または衝突を解消できない候補はreviewへ送る。
- 比較対象は掲載された日本円の買取価格とする。状態、価格保証、店舗またはチャネル、取得日時、原本URLを観測ごとに保持し、条件の等価性を確認できない価格を同条件として統合しない。
- `MVP選定`は自動取得、保存、再利用の許可を意味しない。両情報源について、対象URL、自動取得、User-Agent、取得頻度、raw artifactと抽出履歴の内部保存、sanitized fixture、Card Diggerへの派生集計提供を運営者と書面で合意するまで、Collection Workerによる取得とsource由来fixtureの作成を開始しない。
- 書面許諾は`CP-0070`で追跡する。2情報源のうち一つでも必要な許諾を得られず、MVPの2店舗比較を構成できない場合は、このADRを置換して候補を再選定する。

## Consequences

- Phase 1とPhase 2は、ポケモンカードの識別項目と2情報源の公開形式を前提に進められる。許諾前のcontract設計やtestでは、公開ページ由来の値を複製せず、手作りのsynthetic fixtureを使う。
- 晴れる屋2の単純なJSON schemaと遊々亭の詳細な識別項目を使い、JSONとHTMLの2形式で共通Collector契約を検証できる。
- 両情報源の状態条件は完全には揃わないため、単一の比較金額だけでなく、価格条件と根拠観測をAPIへ返す必要がある。
- 許諾取得がPhase 3の開始条件になる。公開ページを閲覧できること、robots.txtで禁止されていないこと、CORSが許可されていることは、この条件を満たさない。

## Alternatives considered

- カードラッシュ: source内ID、更新日時、版差分を含む構造化データは有力だが、正式提携を除くプログラムによる価格取得をデータ利用方針が明示的に禁止しているため見送った。
- トレトク: set code、番号、レアリティ、言語、ランクA条件が揃うが、規約がコンテンツの無断二次利用とサービスから得た情報の商業利用を禁止しているため見送った。
- ドラゴンスター: source内ID、シリーズ、番号、レアリティ、状態Aを取得できるが、Cloudflare challengeによりrobots.txtと通常取得の安定性を確認できず、ネット買取データの許諾権者も特定できないため見送った。
- フルコンプ: 同じ基準日の店舗別価格を比較できるが、カード単位IDがなく、無名JavaScript配列と名称解析に依存し、運営会社とhostごとに許諾とschemaを分ける必要があるため見送った。
- 3店舗を最初から選ぶ: 比較範囲は増えるが、許諾、parser、状態条件の確認を同時に増やす。MVPではまず2店舗で縦の処理と価値を検証する。

## Validation

- `CP-0004`の[同一カード比較](../sources/source-map.md#同一カードの情報源間比較)を固定fixture設計へ反映し、カード名だけの一致を自動確定しない。
- `CP-0070`で両情報源の書面回答を記録し、許諾範囲と取得間隔を個別source文書へ反映する。
- Phase 3で許諾済みfixtureを使い、必須項目、欠損、版違い、旧価格、0件、構造変更をCollector contract testとparser regression testで検証する。
- 2情報源の許諾、照合精度、価格条件の比較可能性を満たせない場合は、ドラゴンスター、フルコンプ、手動取込を含めて再選定する。
