# ADR-0010: ポケモンカードのMVP情報源候補に3店舗を選ぶ

- 状態: Superseded
- 日付: 2026-09-11
- 決定者: プロジェクトオーナー
- 置換するADR: [ADR-0009](0009-pokemon-mvp-sources.md)
- 置換されたADR: [ADR-0011](0011-no-external-source-inquiries.md)

## Context

[ADR-0009](0009-pokemon-mvp-sources.md)では、ポケモンカードゲームのMVP情報源に晴れる屋2と遊々亭を選んだ。しかし、MVPで必要な自動取得、原本保存、fixture、派生集計提供には書面許諾が必要であり、2候補だけでは一方の不許可または無回答によって2店舗比較を開始できなくなる。

3店舗の観測があれば、2店舗だけでは判別しにくい単独の高値または安値を確認し、実際の観測値を中央値として扱える可能性が高まる。一方、3店舗すべての実装を開始条件にすると、許諾、parser、価格条件、保守の負担が同時に増える。このため、許諾を確認する候補数と、MVPで実装する店舗数を分ける必要がある。

2026-09-11の再確認では、フルコンプ池袋店が[店舗別の買取表](https://www.fullcomp.jp/ikebukuro/kaitori/18872)を公開し、HTML内のJavaScript配列からカード番号、set code、レアリティ、価格、基準日を取得できることを確認した。カード単位の安定IDはなく、列の意味と版・封入状態の一部は名称解析に依存するが、対象を株式会社イントゥ運営の池袋店と`www.fullcomp.jp`に限定すれば、運営主体、host、店舗、価格条件を一つの照会範囲にできる。[robots.txt](https://www.fullcomp.jp/robots.txt)と公開ページには対象pathの自動取得を明示的に禁止する記載を確認できなかったが、自動取得、保存、fixture、派生集計提供を認める記載も確認できなかった。

[ドラゴンスター ネット買取](../sources/dragonstar.md)は、`pid`、シリーズ、カード番号、レアリティ、状態Aを取得できる技術候補である。一方、robots.txtがCloudflare challengeで確認できず、株式会社ジェイフードと株式会社エイアイツーのどちらがネット買取価格データの許諾主体かも確定していない。現在の3候補の検証と同じタスクへ含めず、結果を確認した後に独立して再検討する方が、MVPの開始条件を明確に保てる。

## Decision

- 対象TCGはポケモンカードゲームとする。
- MVPの情報源候補を、優先順に晴れる屋2、遊々亭、フルコンプ池袋店の3店舗とする。
- フルコンプの候補範囲は、株式会社イントゥが運営する池袋店と`www.fullcomp.jp/ikebukuro/`配下の対象買取表に限定する。他店舗、株式会社インスパイア運営店舗、別hostを同じ許諾または同じparserの対象に含めない。
- 3店舗は書面許諾前の`MVP選定`候補とする。対象URL、自動取得、User-Agent、取得頻度、raw artifactと抽出履歴の内部保存、sanitized fixture、Card Diggerへの派生集計提供、停止・削除条件を運営者と書面で合意できた店舗だけを`MVP採用`とする。
- `CP-0070`で3候補へ同じ条件を照会し、回答または期限までの経緯をsource文書へ記録する。
- 3店舗すべてが`MVP採用`となった場合も、最初の1店舗で縦の処理を完成させ、2つ目と3つ目は`CP-0028`で共通契約と保守負担を確認しながら追加する。
- フルコンプにはカード単位の安定IDがないため、情報源内の追跡と重複防止にはsource slug、店舗slug、記事URLまたは記事ID、表示基準日、正規化した行のhash、artifactを組み合わせる。名称からカード番号、set code、版・封入状態を確定できない行はreviewへ送る。
- 情報源横断の自動同定には、TCG、セット、カード番号、レアリティ、言語、版・加工・封入状態を使う。状態、価格保証、店舗またはチャネル、取得日時、原本URLを観測ごとに保持し、条件の等価性を確認できない価格を同条件として統合しない。
- ドラゴンスターは現在のMVP候補に含めない。`CP-0070`の結果後、追加情報源が必要な場合に`CP-0071`で取得安定性、許諾主体、許諾条件を検証して候補へ加えるか判断する。
- `CP-0070`と、実行した場合は`CP-0071`の結果から、必要条件を満たす2〜3店舗を`CP-0072`で`MVP採用`として確定する。Phase 3は`CP-0072`の完了後に開始する。

## Consequences

- 1候補の不許可または無回答だけでMVPの2店舗比較が停止する可能性を下げられる。
- 3店舗を利用できる場合、中央値と外れ値候補を2店舗の場合より評価しやすくなる。
- Collector契約は、公開JSON、通常HTMLに加え、カード単位IDを持たないHTML内配列も表現する必要がある。
- フルコンプ池袋店では、安定IDの欠損、名称解析、列順変更をparser regression testとreviewで扱う必要があり、晴れる屋2と遊々亭より保守負担が増える。
- 許諾照会の対象は3店舗へ増えるが、書面条件を満たさない店舗のCollection Worker、source由来fixture、raw artifact保存は開始しない。
- ドラゴンスターのCloudflareと許諾主体の調査は、現在の3候補を確定する作業から分離される。

## Alternatives considered

- 晴れる屋2と遊々亭の2候補を維持する: adapter数は少ないが、一方の不許可または無回答で2店舗比較を構成できない。
- ドラゴンスターを3番目にする: カード単位の識別項目と状態A価格は有力だが、robots.txtの確認不能、Cloudflareによる取得安定性、価格データの許諾主体を先に検証する必要があるため、`CP-0070`後の別枠とした。
- カードラッシュを3番目にする: 構造化データは有力だが、正式提携を除く価格情報の自動取得をデータ利用方針が明示的に禁止しているため見送った。
- トレトクを3番目にする: 同定項目は充実しているが、規約がコンテンツの無断二次利用とサービスから得た情報の商業利用を禁止しているため見送った。
- フルコンプの複数店舗を同時に選ぶ: 店舗別価格は増えるが、運営会社、host、schema、許諾範囲が広がるため、池袋店だけに限定した。

## Validation

- `CP-0070`で3候補への照会内容、書面回答、無回答時の経緯、許諾範囲、取得間隔を各source文書へ記録する。
- フルコンプ池袋店の代表カードについて、晴れる屋2または遊々亭の同じ印刷仕様へカード名だけに依存せず照合でき、価格条件の差を記録できることを`CP-0070`で確認する。
- 3候補のうち2店舗以上が必要条件を満たさない場合は、`CP-0071`でドラゴンスターを検証するか、別の候補選定でこのADRを置換する。
- フルコンプ池袋店を実装する場合は、許諾済みfixtureを使い、カード単位ID欠損、列数変更、名称解析失敗、基準日欠損、版・封入状態の曖昧さをparser regression testで検証する。
- `CP-0028`で2つ目と3つ目のsource adapterを追加するたびに、同定精度、価格条件の比較可能性、取得成功率、保守時間を測る。
- `CP-0070`の完了後に、ドラゴンスターを追加候補として検証する必要性を`CP-0071`で判断する。
- `CP-0072`で必要条件を満たす2〜3店舗を`MVP採用`として確定してからPhase 3を開始する。
