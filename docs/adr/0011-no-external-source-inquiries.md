# ADR-0011: MVP情報源を公開条件だけで判断し外部照会を行わない

- 状態: Superseded
- 日付: 2026-09-11
- 決定者: プロジェクトオーナー
- 置換するADR: [ADR-0010](0010-pokemon-mvp-source-candidates.md)
- 置換されたADR: [ADR-0012](0012-private-personal-operation.md)

## Context

[ADR-0010](0010-pokemon-mvp-source-candidates.md)では、晴れる屋2、遊々亭、フルコンプ池袋店をMVP候補とし、自動取得、原本保存、fixture、Card Diggerへの派生集計提供の条件を書面照会してから採用する方針を選んだ。

`CP-0070`の公開条件再確認では、3候補のいずれにも必要な利用を一括して許可する公開書面を確認できなかった。フルコンプ池袋店は既存候補と同じ印刷仕様を照合できたため技術的な比較可能性はあるが、利用条件は未確認のままである。`CP-0071`ではドラゴンスターも同じカードを照合できた一方、一覧、詳細、両hostのrobots.txtが通常GETでCloudflare challengeとなり、ネット買取価格の許諾主体も公開情報から確定できなかった。

プロジェクトオーナーは2026-09-11に、情報源の運営者へ外部照会を行わずに進めることを決定した。公開条件だけで必要な権利を確認できない情報源を利用すると、原本を保存して再解析できること、source由来fixtureでparserを検証できること、Card Diggerへ派生集計を提供できることを保証できない。このため、現在の候補をそのまま実装する経路は採用できない。

## Decision

- 情報源の運営者へ、自動取得、保存、fixture、派生集計提供に関する外部照会を行わない。
- 公開された利用条件で、自動取得、raw artifactと抽出履歴の保持、source由来fixtureの保存・再利用、Card Diggerへの派生集計提供を確認できる情報源だけをCollection Workerの候補にする。不明な項目を許可と解釈しない。
- 晴れる屋2、遊々亭、フルコンプ池袋店は、技術調査の記録を残したままMVPのWeb情報源として見送る。公開条件が明確に変わらない限り、adapter、raw artifact、source由来fixtureを作成しない。
- ドラゴンスターは、Cloudflare challengeと許諾主体の不明確さを理由にMVP候補へ加えず、見送る。
- 未送信の照会文案は使用せず、source文書には外部照会を行わない判断と公開条件による結論だけを記録する。
- `CP-0073`で、十分な公開利用条件を持つ情報源を探す経路と、利用者が権利を持つ手動ファイルまたはsource非由来の合成データで縦の処理を先に検証する経路を比較し、MVPの取得経路と完了条件を確定する。
- Phase 3のWeb Collector実装は`CP-0073`の完了後に開始する。取得経路を変更する場合はMVP定義と後続タスクを同じ判断で更新する。

## Consequences

- 運営者との連絡、回答待ち、個別合意の管理を行わずに開発方針を決められる。
- 公開条件に必要な許可がない調査済みの6情報源について、Collection Worker、raw artifact保存、source由来fixture、Card Digger向けデータ提供を開始できない。
- 当初のMVP完了条件である2〜3店舗の反復収集は、代替取得経路を決めるまで満たせない。
- カード識別項目、価格条件、parserリスクに関する既存調査は、将来公開条件が変わった場合や手動入力schemaを設計する場合の技術資料として残る。
- 手動ファイルまたは合成データを採用する場合、それだけではWeb取得の継続性や実データの有用性を検証できないため、検証できる仮説とできない仮説をMVP定義で明示する必要がある。

## Alternatives considered

- 3候補へ書面照会する: 必要条件を直接確認できるが、外部照会を行わないというプロジェクトオーナーの方針に合わないため採用しない。
- 公開ページへアクセスできることを根拠に現在の候補を実装する: 自動取得、保存、fixture、派生利用の条件が不明なままになるため採用しない。
- ドラゴンスターを追加候補にする: 同定項目は有力だが、通常GETがCloudflare challengeとなり、許諾主体も確定できないため採用しない。
- Web情報源の代わりに手動ファイルまたは合成データだけでMVPを進める: 安全に基盤実装を進められる可能性はあるが、元のMVP仮説を一部検証できない。`CP-0073`で公開条件を満たす情報源の探索と比較して決定する。

## Validation

- source文書と情報源マップが、晴れる屋2、遊々亭、フルコンプ池袋店、ドラゴンスター、カードラッシュ、トレトクを`見送り`として扱い、外部照会を予定していないことを確認する。
- `CP-0073`で、選んだ取得経路に必要な利用条件、fixtureの由来、検証可能なMVP仮説を文書化する。
- 公開情報源を採用する場合は、利用条件の確認日と根拠URLをsource文書へ記録し、必要条件に不明点がないことを確認する。
- 手動ファイルまたは合成データを採用する場合は、Web取得を検証済みと扱わず、元データに対する利用権限とfixtureの作成方法を記録する。
